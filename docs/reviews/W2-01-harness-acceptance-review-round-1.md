## Findings

1. **BLOCKER — An incomplete run can receive PASS.** [`harness/release_check.py:129`](/home/shubham/projects/watchlist-triage/harness/release_check.py:129), [`harness/score.py:523`](/home/shubham/projects/watchlist-triage/harness/score.py:523). `_load_run` validates unique row IDs and the row counts against the manifest's own counts, but never checks the expected set of alert/framing IDs from the frozen world. Removing a non-injection TRUE_MATCH in all three framings from each otherwise passing oracle run, then updating the self-reported counts and items hash, leaves the checked conditions and targets satisfiable, so `check` can return PASS without testing AC-1/AC-4 on that alert. The same gap can omit injection pairs. **Fix:** after loading truth, require each completed run to contain exactly every expected main and control-twin item in every framing, with the correct twin flag; mark any mismatch NOT ELIGIBLE. Add a test that removes an alert while keeping the manifest and hash internally consistent.

2. **SHOULD — A superseded run set can still receive PASS.** [`harness/release_check.py:120`](/home/shubham/projects/watchlist-triage/harness/release_check.py:120), [`harness/release_check.py:165`](/home/shubham/projects/watchlist-triage/harness/release_check.py:165). The index's `sets` map is schema-checked but the selected `run_set` is never checked against it. T06's baseline eligibility explicitly excludes superseded sets ([`harness/score.py:695`](/home/shubham/projects/watchlist-triage/harness/score.py:695), [`harness/score.py:710`](/home/shubham/projects/watchlist-triage/harness/score.py:710)); the W2-01 preflight also asks for baseline-like eligibility. **Fix:** mark a selected superseded set NOT ELIGIBLE and test this with a passing set.

3. **SHOULD — Ineligible targets are not individually marked mechanism only.** [`harness/release_check.py:163`](/home/shubham/projects/watchlist-triage/harness/release_check.py:163), [`harness/release_check.py:168`](/home/shubham/projects/watchlist-triage/harness/release_check.py:168), [`docs/acceptance-design.md:35`](/home/shubham/projects/watchlist-triage/docs/acceptance-design.md:35). DEC-W2-01-ELIGIBILITY and the docs say the per-target results are marked mechanism only. The returned `targets` entries remain plain `pass` or `fail`; only the top-level object has `mechanism_only`. A consumer reading a target entry can mistake an ineligible `pass` for release evidence. **Fix:** add the marker to each target entry when ineligible, or make the output shape explicitly require the top-level status and correct the recorded claim.

4. **NIT — The five alternative time settings show only booleans.** [`harness/release_check.py:101`](/home/shubham/projects/watchlist-triage/harness/release_check.py:101), [`docs/acceptance-design.md:28`](/home/shubham/projects/watchlist-triage/docs/acceptance-design.md:28). DEC-W2-01-TIME-RULE says the other five combinations are shown beside the deciding BASE/STRICT_FOUR_EYES values. The result names them, but gives only `lower_than_manual`, not their assisted and manual times. **Fix:** include their time figures beside the boolean so the check output supports the stated comparison.
