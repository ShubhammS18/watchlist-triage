# W2-07-dns-isolation — independent review, round 1

Review range: `dba5c55..HEAD` (`b1c13d0`). Read-only review of the implementation, tests, notes, and the two W2-07 decision records. I did not run tests because the relevant suites use local sockets or a fake DNS server, and this review was requested with no network calls.

## Findings

1. **BLOCKER — `tests/w2_07_isolation/conftest.py:18-19` (gate at `.genesis/project.json:3042`; claim at `.genesis/project.json:1721`).** `WT_SKIP_NETNS=1` is inherited by the fixed pytest gate command. The fixture then skips all 22 namespace-dependent tests, including the zero-query and mutation proofs; the remaining three tests pass and pytest exits 0. The build note records exactly `3 passed, 22 skipped`. Thus the `tests` command gate can pass without the namespace proof, contrary to `DEC-W2-07-NETNS-PROOF`'s statement that the gate can never pass on a skipped proof. This is the suite's only intentional skip branch, and its message does say the proof did not run, but a message does not change the exit status. **Fix:** make the fixed gate command clear `WT_SKIP_NETNS`, or make the W2-07 suite exit nonzero whenever that variable skips the proof under the fixed command. Add a check that runs the exact gate command with `WT_SKIP_NETNS=1` and requires a nonzero exit. Update the decision wording if a green skip is intentionally allowed.

2. **NIT — `tests/w2_07_isolation/conftest.py:22-28`.** A failed `unshare -rnm true` with an empty stderr leaves `problem` empty, so the advertised clear availability failure is bypassed. The later namespace subprocess fails through an assertion whose message may also be empty. **Fix:** treat every nonzero return code as a problem, falling back to `exit status N` when stderr is blank.

3. **NIT — `docs/isolation-design.md:40` (also `:44-45`; decision title at `.genesis/project.json:1708`).** The table says *every way* to make a socket object is refused, while the next paragraph and the test show that `_socket.socketpair()` still creates AF_UNIX socket objects. This does not show a host lookup route, but it overstates the socket-creation claim and echoes the absolute decision title. **Fix:** say “the listed audited socket-creation routes” in the table and qualify the decision title or text with the documented `_socket.socketpair()` exception.

## Checks with no finding

- For the ordinary, accidental, and prompt-injected Python routes reviewed, `socket.__new__` blocks socket objects before name-taking C methods can resolve an address. The audited direct lookup APIs, process-launch routes, and `ctypes` route remain blocked. The unaudited `_socket.socketpair()` route is AF_UNIX only in the tested environment and does not accept a `(host, port)` address. I found no in-scope route in this diff that sends a query or creates an internet socket under the current guard.
- The T04 `connect`, `sendto`, `sendmsg`, and `bind` probes still run against the control and guarded child; their expected refusal moves to `socket.__new__`. Their older audit events remain covered by hand-raised probes, and the network-block mutation still removes the entire network event group. I found no loss of those earlier guarantees.
- The control asserts at least one counted DNS query for each of the 19 distinct route names. The agent side asserts both zero counted queries and the exact expected refusal for every route, so a zero caused merely by a broken counter or a route not running would not satisfy these checks. This proof covers the enumerated routes on the tested Linux/Python configuration, not arbitrary hostile code inside the process.
- README and `docs/README.md` describe the skip and the pending review consistently. The gate-pass implication in the decision record remains incorrect until finding 1 is fixed.
