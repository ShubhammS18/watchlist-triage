# W2-10 release-runs design: round 1

Review scope: `docs/w2-10-release-runs.md` against the W2-10 outcome, the six named decisions, `docs/w2-08-release-protocol.md`, and the `baseline_run` wrapper. Design only; no gates or model calls were run.

1. **BLOCKER — The check commands make their own working tree dirty (lines 212–218).** W2-08's release check requires a clean tree (`docs/w2-08-release-protocol.md:146–149`). Shell redirection creates or truncates `release/check-frozen.json` and `release/check-fresh.json` before `acceptance` starts, so the check can report NOT ELIGIBLE solely because the output file is untracked or modified. Repeating it with `cmp` has the same problem. **Fix:** run each check from a clean checkout with output redirected to a file outside that checkout; compare the two external files, then copy the agreed bytes into `release/`, commit them, and verify them again at the publish tag. Spell out how expected nonzero result codes are handled.

2. **BLOCKER — The publish command has no staged publish change (lines 222–235).** Step 2 says to commit both check outputs and push; step 4 then requires a clean tree and runs `git commit -m ...` without `git add`. With no sign-off, there is nothing to commit. With a sign-off row added but unstaged, `git commit` also fails. Thus the documented publish commit and tag cannot be made exactly as written, including for FAIL or NO FRESH WORLD. **Fix:** stage the final allowed log/check files and make the publish commit before requiring a clean tree; if they were already committed, explicitly create an empty publish commit or tag that final committed state. Test that path for a result needing no sign-off.

3. **BLOCKER — G1–G11 do not enforce the recorded stop rules (lines 98–102, 309–338).** `DEC-W2-10-CHOICES` requires stopping before the next run after a run over USD 0.30 or W2-10 spend over USD 2.00; `DEC-W2-10-STOPS` adds the wrapper's greater-than-2% refusal checkpoint. G6 checks that spend is a decimal and G9 checks the total, but neither rejects a later run after a reported breach. The dry-run breakages omit all three cases. A release violating these recorded rules could pass the gate. **Fix:** derive refusal shares from committed items, check the logged spend and run sequence against all three stop thresholds, and add one failing dry-run case for each. State the limit that the gate cannot verify Console readings or the actual wall-clock order.

4. **BLOCKER — G8 can accept no completed rehearsal on the practice world (lines 104–122, 310–322).** It requires only a rehearsal row, an ancestor agent commit, and a checkpoint for a completed or aborted row. A killed-only row passes those checks; a row for a different world or candidate can also pass. The W2-10 outcome and W2-08 protocol require a rehearsal run of the release candidate on the practice world before the freeze. **Fix:** define and retain verifiable rehearsal evidence (at least its manifest, world identity, agent identity, result, and cost), require a completed rehearsal of the frozen candidate before the freeze, and add dry-run failures for a killed-only or wrong-world rehearsal. If this is deliberately a human-only check, state that the gate does not prove the rehearsal requirement.

5. **SHOULD — The annotated freeze tag evidence will not match G11 as specified (lines 139–142, 314).** `git tag -a` creates an annotated tag; `git ls-remote --tags origin release-1-freeze` shows the tag object's hash, while G11 says the `refs/tags/` line names the freeze commit hash. The prescribed evidence can therefore fail its own check. **Fix:** capture and check the peeled `refs/tags/release-1-freeze^{}` line (and the corresponding second-freeze tag when used), while retaining the tag-object line if useful.

6. **SHOULD — The all-ten-rejected path has no executable check-and-publish instructions (lines 165–166, 201–218, 273–277, 307–317).** It says to make no fresh runs, but the later steps still require copying `$REL/out-fresh`, supplying `<set>` to the fresh check, and committing a fresh check output. There is no fresh output folder or run-set ID in that branch. G6's fresh-world index/log comparison also needs an explicit exception. **Fix:** give the exact NO FRESH WORLD command, expected output files and exit code, log row, and G6 behavior when no fresh run set exists; include this branch in the dry run.

7. **SHOULD — Crash recovery assumes a complete started index entry (lines 190–198).** A WSL crash can interrupt creation of `index.json`, a run folder, or a checkpoint. The instruction to leave a `started` entry, log a replaced run, and rerun with `--rerun-cause` cannot be followed if the index is missing or unreadable. The wrapper decides whether a cause is needed by reading the last index entry (`baseline_run/wrapper.py:71–75, 99–101`). Its pre-run benchmark refusal is a separate no-run case, as lines 67–70 say. **Fix:** document recovery for no entry, a sound started entry, and a damaged/partial index or folder; stop and preserve evidence for the last case, and say how any paid but unindexed attempt is logged and counted. Do not claim every guard kill leaves an index entry.

8. **SHOULD — The run commands omit the fresh invocation and fail on literal placeholders (lines 170–180, 212–218).** The only run command targets the frozen world; `[--rerun-cause "TEXT"]` is documentation syntax, not a shell command to paste, and `<run_id>`/`<set>` are never derived. This matters after a refusal or crash, when the wrapper requires the cause for the same output folder. **Fix:** show separately executable first-run and rerun commands for each world, obtain the run ID and set ID from the output index, and state which values to use when a wrapper refusal created no index entry.

9. **NIT — The freeze section names a freeze commit but never shows how to make it (lines 124–140).** The only displayed commands tag and push the current HEAD. **Fix:** add the explicit final stage/commit step and identify the resulting full commit hash before tagging, while keeping the stated clean-tree and drift checks.

The design otherwise carries over the safety-count rule for both worlds, the fresh-world rates as information only, replacement and five-run limits, checkpoint requirements, seed replay, frozen-file restrictions, and publication of FAIL/NOT ELIGIBLE. Its stated limits on unrecorded runs, Console truth, push order, and actual run order are real limits of a committed-file gate.
