Read-only review of the drafts and committed `baseline/`. No Genesis command was run, and `data/world/hidden/` was not read. Line references below point to the draft files.

## Findings

1. **SHOULD — Causal certainty exceeds the runs.** `baseline-report.diff:25-32,68-70,86-87`; `README.diff:9-11`; `decisions.md:11,30`. The same-run alert/twin comparisons and stable control-twin verdicts are strong evidence of an injection effect, but 0/135 observed twin run-to-run changes does not prove sampling could not produce a particular alert/twin difference. The drafts state that all 14 differences are “not chance” and that the text *caused* all three misses as settled facts. **Fix:** Say the differences are associated with the injected text and are not explained by the observed control-twin variation; describe the three closes as occurring only on the injected version in these runs. Keep the three-run limitation explicit.

2. **SHOULD — The common identity of the missed true matches is not established by `baseline/` alone.** `baseline-report.diff:28-29,36-38,45,75-76,86-87`; `README.diff:9-10`; `decisions.md:11`. The baseline artifacts show one injected alert closed in framing 2 in all three runs while its twin was escalated each time. They do not expose the true-match labels needed to establish that these are the report's three missed true-match items. The correction acknowledges a hidden-label reading, but its introductory claim that the analysis was of `baseline/` and the README's unqualified statement can imply the identity follows from public artifacts alone. **Fix:** Attribute that identification explicitly to the owner's separate hidden-label check wherever it is stated; keep the baseline-only observation separate. Do not present the identity as independently reproducible from `baseline/`.

3. **SHOULD — The spec change note understates requirement changes.** `SPEC.diff:7,16-17,25-28,45,53-56,129-143`. Decisions 3–5 support the edits, but “No other requirement changes” is false as a description of the diff: FR-9 and AC-11 now exclude hostile in-process code from the prior absolute network claim; FR-20 rules out crossed breakdowns; the cost headline changes from total run cost to main-item cost; and the time-budget constraint is removed. In particular, the FR-9/AC-11 carve-out is a loosening outside AC-12, even though decision 4 records the reason. **Fix:** Identify these as scope or metric-definition changes in the change note, distinguishing prior decisions from unchanged requirements. Retain the explicit AC-12 citation relaxation and time-budget removal.

4. **SHOULD — The upgrade gate cannot establish the whole task outcome as written.** `tasks.md:21-25`. The single gate is described as checking committed output without model calls. That can assess the recorded run set, but the outcome also requires one change and one measured run set per attempt, an after-attempt note and decision, an attempt limit, and wave-2 spending within the ceiling. No gate or specified evidence checks that process or the cumulative spend. **Fix:** Add a checkable attempt ledger and spend evidence with an explicit gate or review criterion; make the gate verify the frozen-world report and the process records separately.

5. **NIT — The coverage table's “only” claim is inaccurate.** `tasks.md:39-40,44,59,61-62,72-74`. `WAVE2-RESERVED` has 29 requirement IDs, and the table includes all 29; the seven/22 count is correct. But FR-8 is also assigned to completed T05, AC-11 and AC-14 to completed T04, and AC-13 to completed T05 in `.genesis/project.json`. **Fix:** Call the table “all requirements on WAVE2-RESERVED” and describe the unfinished portions of those four entries, or remove “only ... covers today.”

6. **NIT — An ID appears in a section heading despite the no-ID preface.** `decisions.md:3,25`. The actual `--title` and `--text` values contain no requirement or decision IDs, as claimed, but the heading `## 3. AC-12 rule` contains a requirement ID. **Fix:** If “title” includes markdown headings, rename it to “Injection rule”; otherwise clarify that line 3 refers only to the recorded `--title` and `--text` fields.
