# W2-02 agent upgrade — independent review, round 1

Range: `5da6ad1..HEAD`. Read-only repository review; no network or paid model calls. I did not open `data/world/hidden/`.

## Findings

1. **BLOCKER — A valid but wrong model answer can close an alert the rubric requires to escalate.** `triage_agent/recommend.py:60-63` turns every syntactically valid `NO_LINK` into `CLOSE` without checking the note's content. The public evidence for `ALT-0327` has a hard ID conflict and a note explicitly saying the customer is the listed person. I passed that public bundle through the real guarded child with a scripted, schema-valid `NO_LINK`; the result was `CLOSE`, `system_failure=False`. The attempt log at `docs/w2-02-attempts.md:23` records an actual earlier false close of this kind for `ALT-0524`'s twin. The revised prompt reduces the observed error but cannot enforce the rubric. **Fix:** make any uncertain or semantically inconsistent note answer escalate; for a hard guarantee, independently recognize identity-link claims before accepting `NO_LINK`, or require human confirmation before a note-dependent close. Add a regression using the public `ALT-0327` and `ALT-0524` note patterns.

2. **BLOCKER — The cost check can call an estimate a proven upper bound and return PASS.** `harness/release_check.py:115-145` substitutes a later success's input tokens, or prompt UTF-8 bytes, for an unreported failed call, and uses the *requested* model's price even though the failed attempt has no reported model ID. A successful retry does not report what the failed call was billed; a comparison of other successful calls with their byte lengths proves no bound for a failed call. In particular, `cost_bound` returns no problems for an isolated failed call with `prompt_bytes=0` and no successful calls, while the request can still have protocol input tokens. `harness/run.py:86-90` counts message content bytes only. Thus the eligibility check can PASS when the failed call's billed cost is unknown. **Fix:** obtain a provider-backed maximum for failed calls including token and model pricing, or classify any call without verifiable usage as NOT ELIGIBLE. Keep the known-cost figure informational.

3. **SHOULD — The named rule-code hash omits shared decision code.** `triage_agent/record.py:9-17` hashes four files in `triage_agent/`, but `triage_agent/recommend.py:12-15` also uses `baseline_agent/payload.py`, `baseline_agent/recommend.py` and `baseline_agent/agent.py` to construct inputs, validate child results and build failures. Changing those modules can change a verdict without changing `rule_code_sha256`. The clean git commit in the run-set inputs does change, but the manifest's claimed rule-code hash does not cover all decision code. **Fix:** include those shared modules in the recorded code digest, or rename and document the digest as only the local triage package hash.

4. **SHOULD — Acceptance does not bind the prompt and rule-code hashes in a loaded manifest to the run-set inputs.** `harness/score.py:472-505` validates the run-set hash and the price/time hashes, but does not check `sha256(prompt.text) == prompt.sha256 == run_set_inputs.prompt_hash` or `prompt.rule_code_sha256 == run_set_inputs.rule_code_hash`. `harness/schema.py:117-119` checks their shape only. The real harness writes matching values, but an altered run artifact can pass acceptance while stating a different prompt or rule-code hash. **Fix:** add these equality checks to manifest validation, and mutate each field in a W2-01 test.

5. **SHOULD — The generator-separation guard is narrower than its claim.** `tests/w2_02_agent/test_agent_static.py:19-32` catches literal `import` statements only, so dynamic imports in parent-side agent modules pass. Lines 48-57 reject full source literals of at least 20 characters and frozen rendered snippets, but do not cover short fragments, concatenated strings, or rendered templates on another seed. Current source has no such import or copied note text; the issue is the guard's ability to keep that invariant. **Fix:** define the exact threat model and test a dynamic-import mutation plus rendered template variants (or use a stricter parent import allowlist).

6. **SHOULD — The public limits omit applicable caveats.** `README.md:78-85` says only baseline reasons may quote synthetic customer details, although `triage_agent/recommend.py:62-66` includes free-form model reasons in upgraded results. It also omits the self-asserted reviewer identity limit required by `SPEC.md` NFR-7. `docs/w2-02-report.md:98-114` does not state that citation accuracy checks IDs, not whether the written reason is supported. **Fix:** make the reason disclosure apply to all model results, add the reviewer-identity limit to README, and state the reason-support limit beside the W2-02 result.
